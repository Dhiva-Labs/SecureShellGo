# Store graphics — what's here, what Play requires, what's still needed

This directory holds the generated Play Console graphic assets. Screenshots
are **not** included — they need a running app on the emulator/device, which
is out of scope for this pass (another agent is using the emulator
concurrently). The shot list below is ready for the PM to capture directly.

## Generated assets

### `icon-512.png` — hi-res store icon
- **512 × 512 px**, RGB, no alpha channel (verified programmatically —
  `mode == "RGB"`, `"A" not in getbands()`)
- No baked-in rounded corners or shadow — Play masks the icon itself per
  device/launcher shape, so the square is left full-bleed
- No text, just the app's `>_` prompt motif
- Colours and geometry match the shipping launcher icon
  (`android/app/src/main/res/mipmap-xxxhdpi/ic_launcher.png`, sampled:
  background `#0D1117`, green `#3FB950`) and `lib/theme.dart`
  (`AppTheme.terminalBackground`, `AppTheme.accent`) — redrawn as vector
  shapes at full resolution rather than upscaled from the 192px launcher
  bitmap, so edges are crisp
- Generated by `store/scripts/make_icon.py`, geometry shared with the
  feature graphic via `store/scripts/motif.py`

Satisfies Play's hi-res icon spec: 512×512, 32-bit PNG, no transparency.

### `feature-graphic-1024x500.png` — store listing feature graphic
- **1024 × 500 px**, RGB, no alpha channel (verified programmatically)
- 24-bit PNG (one of Play's two accepted formats for this asset, the other
  being JPG)
- Dark gradient background between the app's two surface colours
  (`#0D1117` → `#161B22`), an oversized low-opacity `>_` watermark on the
  right, the app name set in the same monospace family the terminal uses,
  and a one-line factual tagline plus two feature callouts — no
  screenshots, no device frame, no fake UI chrome, no claims text
- The **lower-left region is left calm** (background only, no text or
  glyph) because Play overlays the app icon + title chip there when this
  graphic is shown as a promotional card
- Generated by `store/scripts/make_feature_graphic.py`

Satisfies Play's feature graphic spec: exactly 1024×500, JPG or 24-bit PNG.

Both assets were opened with Pillow after generation and their size/mode
asserted in code — see the `main()` function of each script for the actual
checks, not just a visual read.

## Screenshot shot list

Play requirements (per the brief):
- **Phone**: 2–8 screenshots, 16:9 or 9:16 aspect ratio, minimum dimension
  320 px, maximum dimension 3840 px
- **Tablet**: since SecureShell Go has real tablet layouts
  (`lib/services/layout_breakpoints.dart`'s `WindowSizeClass`, exercised in
  `SessionScreen`'s side-by-side terminal+file-browser and
  `HostListScreen`'s wide-screen host grid), include both a **7" and a
  10" tablet** screenshot set — same aspect-ratio/dimension rules, captured
  on emulator profiles/AVDs sized for each (e.g. "Nexus 7"-class ~7",
  "Pixel Tablet" or "Nexus 10"-class ~10")

Capture with light, realistic data — a couple of saved hosts with plausible
names, a real (or realistic-looking) directory listing — never real
credentials, IPs, or personal file names.

the 2–8 budget)

### Capture notes for whoever drives the emulator
- Use `flutter run` / the existing debug build — this pass did not touch
  `android/`, build files, or the emulator, so nothing here affects buildability.
- Match each screenshot's device frame/resolution to a real Play-supported
  size; don't hand-crop a screenshot to force an aspect ratio, since that's
  exactly the "stretched/low-quality" failure mode Play rejects for.
- Strip the status bar of anything identifying (real Wi-Fi name, real
  battery/time is fine and normal) before export if the capture tool
  doesn't already do it.
